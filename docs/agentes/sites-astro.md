# Sites em código: Astro (2026-11-06)

O usuário: "quero ter suporte pra importar um site em astro… conectar o repo com o github… usar como um wysiwyg pra editar o astro e publicar"; depois "crie tudo conforme seu plano… em local em uma branch nossa". O site continua sendo Astro no repositório dele: não vira Elementor nem entra no canvas do Space.
- **Onde**: `/sites` (lista e ligação, `src/pages/sites/CodeSites.tsx`) e `/sites/:siteId` (editor em tela cheia com a Iara ao lado, `SiteEditor.tsx`); menu "Sites em código" junto de Projetos (módulo `projetos`). Roda **nesta máquina**: plugin `scripts/sites/vitePlugin.ts` no `npm run dev` e no conector, pelo canal dos agentes (`sites:chamar`/`sites:resposta`/`sites:estado`/`sites:log`, tipos em `src/features/sites/protocol.ts`, aba em `link.ts`).
- **Ligar**: um repositório do GitHub pelo `gh` desta máquina (clonado em `~/SuperElements/sites/<dono>__<nome>`, `SUPERELEMENTS_SITES_DIR` muda) ou uma pasta que já está aqui; só aceita projeto com `astro` no package.json. O registro fica em `~/.superelements/sites.json` (por conta, `accountId`), fora do repositório, igual para o dev e o conector (`registry.ts`).
- **Prévia** (`preview.ts`): instala as dependências se faltar (npm/pnpm/yarn/bun pelo lockfile) e sobe o `astro dev` do próprio site pela API do Astro (`~/.superelements/astro-runner.mjs`, porta 4321–4399), com duas coisas só na prévia: `devToolbar.enabled` (é o que faz o Astro marcar cada elemento com `data-astro-source-file`/`-loc`) e o script de edição (`overlay.ts`, `injectScript('head-inline')`). O `astro.config` do site não muda. A barra do Astro fica escondida e **apaga as marcas do DOM ao abrir** (`apps/audit/annotations.js`): o script copia cada marca para `data-se-file`/`data-se-loc` por MutationObserver antes disso. A marca `loc` é a posição logo depois da tag de abertura. Se a preferência global da barra estiver desligada nesta máquina, não há marcas (`npx astro preferences enable devToolbar`).
- **Editar** (`source.ts`): clique escolhe o elemento (caixa violeta com tag e componente), duplo clique edita o texto ali mesmo (Enter salva, Esc desfaz); o painel mostra os trechos de texto, os atributos (link, alvo, title, src, alt…), "Trocar imagem" (vai para `public/superelements/`) e "Onde mais esse texto aparece". O arquivo é lido pelo `@astrojs/compiler` do próprio site; posições em **bytes**. Texto escrito no elemento troca no lugar exato, mantendo espaços, `<strong>`, `<br>` e entidades (`&nbsp;`). Texto que vem de dados (`{item.title}`, props, listas no frontmatter, JSON/MD de conteúdo) é procurado em `src/`, `content/` e `data/` e trocado onde está escrito, com o escape do lugar (HTML, string JS, JSON, YAML); aparecendo em mais de um lugar, a pessoa escolhe ou pede à Iara. Atributo vindo de expressão não é editado à mão.
- **Iara no site**: no editor a conversa é `site-<id>`; `chatPlugin.ts` (`isSiteChat`) roda o Claude Code ou o Codex **na pasta do repositório do site**, com regras próprias (mudar arquivos direto, não rodar `astro dev`, não fazer commit nem push). O elemento escolhido vai pela tela da Iara (`useIaraScreen`). A prévia recarrega sozinha com o que o agente salva.
- **Publicar** (`git.ts`, `PublishDialog.tsx`): mostra os arquivos e o diff; "Publicar no site" faz commit na branch principal, rebase sobre o `origin` e push (a hospedagem ligada ao GitHub publica; a Vizor sai pela Hostinger a partir da `main`); "Mandar para revisão" cria `superelements/<data>`, sobe e abre o PR pelo `gh` (falhando o PR, avisa e a branch fica). Nas edições seguintes a revisão recebe os commits; "Voltar para main" sai dela. "Descartar" volta os arquivos ao último commit e apaga só os arquivos novos do editor (`public/superelements/`). O estado do git é relido a cada 5 s (o agente também muda arquivos) e avisa quando o GitHub está à frente ("Atualizar" = `pull --ff-only`).
- **Testado** em 2026-11-06 com uma cópia da Vizor e um remoto local (nada foi ao GitHub): textos com `<strong>`/`&nbsp;`, texto de lista no frontmatter com aspas, atributos, imagem, publicar direto (commit no remoto), revisão (branch subiu; PR não abre num remoto local), descartar, e a Iara rodando na pasta do site; clique e duplo clique no Chrome headless; telas pelo harness `.space/_harness/sites/` (o canal real do dev, sem login). Testes: `scripts/tests/sites-source.test.mjs`. Não testado: o app publicado com o conector, o repositório real da Vizor e um PR real.
