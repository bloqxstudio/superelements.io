# Página de cliente e componentes no Space

Each Space project is a client. When the user asks to analyze or change a page, or to create, change or reorder a section, the deliverable is that change made in the project's page in the Space canvas (through `scripts/space/space.mjs`), not a new template. Follow `.claude/skills/cliente/SKILL.md`.

Components (2026-10-06, rebuilt the same day at the user's request: "componentizar qualquer coisa", no separate area for components, edited in place): anything can become a component, a whole section or one layer inside it (container, button, heading). Each use lives in its page as a linked copy, editable right there; changing one use (in the canvas, by `push`, by undo) changes all uses, each keeping its own element ids and hand-made pins. What is linked is chosen per component (the user, 2026-10-06: "somente estilos, textos podem ser diferentes… talvez escolher, pq um hero pode ser com o mesmo texto, um botao pode ser diferente"): by default (`texts: 'own'`) only style and structure are linked and texts, links, images and lists are each use's own (`isContentSetting` in `src/features/space/editor/contentFields.ts`); "Iguais em todos" (`shared`) links the content too, starting from the selected use. A component inside another follows its own choice. An Elementor template holds one content, so on publish the most-used version becomes the template and a use with its own texts goes inside its page; a page whose header or footer has its own texts takes both inside, on Canvas, and is left out of the Theme Builder conditions (`templateUses`, `themePage`) (`syncComponents` in `src/features/space/components/components.ts`, run by a store subscription in the same undo step). The registry is `SpaceComponent[]` in the canvas (`components` in the store and the saved project); a whole-section use has `SectionNodeData.component`, a layer use has the Elementor setting `_se_component` (Elementor ignores it; it is stripped on publish). Uses are cyan (`COMPONENT_COLOR`) with the component icon and name in the canvas label, the selection box and the layers, with no side markers. Clicking a use shows the component card on top of the Style tab (name, the other uses as chips that jump there, header/footer role, publish, "Separar este", "Desfazer componente"); a section or page lists the components inside it. "Transformar em componente" is in the layer toolbar, the section actions, the section menu and Ctrl+Alt+K; the Style tab then opens with the name field selected to type the name (the user asked to name components), and turning a section into one offers to link the copies with the same design on other pages (texts may differ). Components are also renamed in the card and with the pencil in the Inserir list. Duplicate, copy and paste keep the link; the Inserir panel lists the project's components ("Componentes do projeto") to click or drag in. A component never goes inside a use of itself. A section component can be the site header or footer (`role`): new pages come with it (`siteFrameSections`). Publishing (Elementor Pro or PRO Elements): the header and footer become Theme Builder templates (include/general minus the published pages without them; pages that use them go on Elementor Full Width without them inside); a section becomes a saved container used by the Template widget; a widget becomes a Global Widget (only through the Connector plugin 0.3+: the widget type lives in `_elementor_template_widget_type`, which the WordPress API cannot write); a container inside a section has no native template and goes inside each page. Publishing a page saves the components it uses that are not on the site yet; updating a component's template is its own explicit action (it changes every page of the live site). Import is the way back: Theme Builder headers and footers, Template widgets and Global Widgets come back as the real template content, as components linked to the same template, reusing the canvas component and refreshing its uses (`resolveTemplates`, `importSiteGlobal` in `src/features/wordpress/siteImport.ts`). Template access: Elementor blocks every REST route containing `elementor_library` for non-admins in `rest_pre_dispatch`, so the browser preflight gets 401; template content goes through the Supabase function `supabase/functions/space-wordpress-library` (server side, with the project connection; deploying it is the user's call) and, without it, through the Connector plugin (`superelements/v1/parts`). The Theme Builder list and conditions come from the Site Editor REST, which the browser can call. The WordPress API cannot install a plugin that is not on wordpress.org. Never work around the guard with route tricks. The plugin zip in `public/wordpress/` is rebuilt with Windows `tar.exe -a`; tests in `.space/_componentes/` (`cdp-comp2.mjs` canvas, `cdp-wp-comp2.mjs` and `cdp-wp-global2.mjs` against the WordPress Playground in `wp/`). Agents use `space component`.

Revisão de 2026-11-13 (editor do Space): as operações de página (inserir, tirar e mover seção, criar e excluir página) ficam em `src/features/space/pages/canvasOps.ts`, funções puras usadas pelo store e pela ponte dos agentes (`bridge/client.ts`); o que o agente apaga vai para a lixeira (`emitRemoval`), e excluir página pelo agente leva os textos/paletas ligados só a ela. O hash que protege edições à mão cobre todo o `data` da seção. Salvamento de outra pessoa ou aba não zera mais o desfazer: cada passo guarda a época da sincronização e, ao desfazer/refazer, o que foi criado, apagado ou mudado de fora depois do passo fica como está (`src/features/space/history/remoteHistory.ts`); testes em `scripts/tests/space-canvas-ops.test.mjs`.
