# Project instructions

## Working on a client page

Each Space project is a client. When the user asks to analyze or change a page, or to create, change or reorder a section, the deliverable is that change made in the project's page in the Space canvas (through `scripts/space/space.mjs`), not a new template. Follow `.claude/skills/cliente/SKILL.md`.

## Prospecting (finding Superelements clients)

Created 2026-10-03: businesses of a city and niche (lawyers, doctors, psychologists…), with what their site runs and an opportunity score.

- Engine: `scripts/prospects/engine.ts` (Node). Screen: `/prospeccao` (header "Prospecção"), only with the dev server, which opens the sites (`scripts/prospects/vitePlugin.ts`, same-origin only). Terminal: `npm run prospectar -- --regiao "São Paulo, SP" --nichos advogados,psicologos [--bairros "Pinheiros;Moema"] [--fonte google]`; `--nichos-prontos` lists the niche ids.
- Types, niches, score and CSV live in `src/features/prospects/` and are loaded by Node too: keep their imports relative with the `.ts` extension and the syntax erasable (no enums).
- Sources: Google Maps read for free (`maps`, the default, by the user's choice on 2026-10-03: "não quero ter o custo"), OpenStreetMap (`osm`, free, partial) or the paid Places API (`google`, `GOOGLE_PLACES_API_KEY`). The free Maps reader uses Maps' internal search address (`/search?tbm=map`, taken from the search page, then only the coordinates and `!8i` offset change); about 300 places per point. Google's terms do not allow this reading: one request at a time with a pause, stop at the first block and keep what was found. If Maps changes, `mapsTemplate`/`mapsPage`/`mapsBusiness` in `engine.ts` need adjusting. The permission system blocked agents from running it, so the user runs Maps searches. Never invent businesses or contacts.
- Coverage (`maps` only): `centro` is one deep search at the city center (or one per neighborhood typed); `cidade` lays up to 36 points inside the city outline (Nominatim polygon) and splits a point into four where Maps fills all ~300 slots with new places (two levels). Businesses from neighboring cities are dropped.
- Detection reads only the home page (and the contact page when it has no e-mail): WordPress, Elementor/Pro and versions, other builders, theme, contacts and the footer credit ("Desenvolvido por …" = the agency, a lead for the Agência plan). The "outdated" thresholds in `score.ts` are dated; update them as WordPress and Elementor release.
- Buying signal (2026-10-03, the user: "só tem site quem faz anúncio e por isso que compram"): the scan reads paid-ad traces (`ads`: Google Ads conversion tag, Meta/TikTok/LinkedIn pixels; Tag Manager alone is a weak sign) and sales tools (`sales`: online booking such as Dietbox, WebDiet, Calendly; course checkouts such as Hotmart, Kiwify; WooCommerce). They raise the score, show an "Anuncia" badge and the "Só quem anuncia" filter, and the sales script opens with them. A tag means the site has it, not that an ad is live: each lead has links to Google Ads Transparency (by domain) and the Meta Ad Library (by name) for a person to check. Wix and Tag Manager can load pixels the HTML does not show, so the count is a floor.
- Results stay in `data/prospeccao/` (gitignored): they hold contact data of people. Do not commit them or send them to other services without the user asking.
- Funnel (2026-10-03, the user's request): the "Funil" tab of `/prospeccao` holds the opportunities in `data/prospeccao/funil.json` (`scripts/prospects/funnelStore.ts`, types and stages in `src/features/prospects/funnel.ts`). Stages: Mapeado → Fila da página → Página pronta → Contatado → Em conversa → Proposta → Fechado / Perdido. Each card keeps the lead snapshot, the Space project name, the outreach video, the next step and notes.
- **The studio is Avence Studio** (https://avencestudio.com/, @avencestudio, São Leopoldo), the user's own studio: every message to a prospect is signed "Aqui é [seu nome], da Avence Studio". Superelements is the product behind it and never appears to the end client (the user's decision, 2026-10-04: two separate brands).
- **We sell a service, as an agency, not the Superelements product** (the user's decision, 2026-10-03): the new site for a one-time price (default R$ 1.000 in the funnel settings; the user also mentioned R$ 350) and an optional monthly plan to look after it. Never put the Superelements plans (Produto, Completo, Agência) or product features in an offer, a sales script or a client-facing text. Each opportunity has an offer (service, price, monthly) and a sales script (`SalesBrief`: what we deliver, how to offer, the best way, what the new site solves, objections), drafted by `draftOffer` (`src/features/prospects/offer.ts`) and adjusted by hand; the funnel shows the open value (from "Fila da página" to "Proposta"). When an agent finishes a page from the queue, it rewrites that opportunity's script with what it found on the site (as done for the São Leopoldo lawyers).
- Cards move between stages by drag and drop (or the advance button); a drop can be undone from the notice.
- A site the user points to outside the searches: `npm run prospectar -- --site <url> --nichos advogados --regiao "<cidade, UF>" [--nome "<empresa>"]` reads it (`leadFromSite`, source `manual`, id `site:<domínio>`) and puts it in "Fila da página".
- "Rodar a fila" means: `npm run prospectar -- --fila` lists the businesses in "Fila da página"; each one becomes a Space project with a new Home through `/cliente` (one agent per business, each with its own `SPACE_SESSION`, as done for the São Leopoldo lawyers). When the page is done, move the card to "Página pronta" and fill the project and the video. Nothing goes to the business (link, message, publish) without the user.
